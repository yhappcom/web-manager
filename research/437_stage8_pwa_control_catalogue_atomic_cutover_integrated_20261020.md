## HISTORY / PROBLEM → PRINCIPLE

Service Workers replaced opaque AppCache updates with programmable versioned caches. LogMate separates immutable shell/font caches by build, but keeps mutable release pointers, manifests and client assignments in a single Cache API JSON. A Promise queue only serializes within one worker global. Study 436 established source-derived cross-worker lost-update risk. **New finding:** merely moving new-worker writes to IndexedDB does not coordinate with an *old* worker still writing the legacy Cache JSON during installation. An early migration snapshot can be stale before activation. A transaction on IDB is not a transaction across CacheStorage and IDB.

**Principle:** move release metadata only through a one-way, writer-fenced activation cutover; preserve all legacy caches and user data; never claim cross-store atomicity.

## SYNTHESIS — twelve integrated decisions

1. **State split:** immutable `logmate-shell-<build>` and `logmate-fonts-<set>` remain in Cache API; mutable current/previous/candidate/versions/client mappings belong in a dedicated transactional release-metadata store, not owner-record Sembast.
2. **Mixed writers:** v3 IDB transactions cannot serialize v2 writes to Cache JSON. Do not copy legacy state at install and call it authoritative.
3. **Install:** download/hash-check immutable v3 candidate bytes without mutating legacy `CONTROL_KEY` or promoting v3; do not enable `skipWaiting` as a shortcut.
4. **Cutover:** after old controlled clients drain and v3 `activate` fires, read the *latest* legacy snapshot and verify referenced manifests/caches. This depends on current no-`skipWaiting` semantics and must be runtime-tested.
5. **Atomic metadata:** commit migration marker, retained predecessor manifest/pointer, verified candidate pointer and client assignments together in one short IndexedDB `readwrite` transaction. Idempotent retries must not re-import stale legacy state after migration complete.
6. **Transaction discipline:** never await `fetch`, `caches.match`, `crypto.subtle.digest` or UI work *inside* the IDB readwrite transaction. The current async `promoteInControl` callback cannot be copied unchanged. Pre-verify bytes; mutate metadata synchronously in request success callbacks.
7. **Cross-store gap:** metadata commit cannot atomically guarantee CacheStorage contents. Continue serve-time size/SHA checks; missing/evicted assets fail closed into repair, not cross-version network fallback.
8. **Concurrent assignments:** IDB serializes writers using the same object-store protocol; it does not fence any legacy Cache writer or prove cross-browser execution.
9. **Schema upgrade:** close on `versionchange`, expose `blocked`, handle abort/quota/crash, do not silently use old control key after migration.
10. **Rollback:** current `ROLLBACK_TO_PREVIOUS` intentionally returns `NOT_ROLLED_BACK`; preserve fail-closed. Reverting to a Cache-only old Worker after IDB cutover would reintroduce split-brain unless a separately validated bridge exists.
11. **Owner-data isolation:** never delete Sembast records, outbox, CacheStorage or `.lbk` backups to repair release metadata. Worker activation failure is *not* proven to restore the old controller automatically.
12. **Human/measurement:** distinguish offline-ready, staged update, reload, repair and record preservation. A Worker transaction is not Sync acknowledgement or backup verification. Telemetry must exclude auth tokens, email and flight records.
