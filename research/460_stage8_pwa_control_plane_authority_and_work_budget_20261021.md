## HISTORY / PROBLEM → PRINCIPLE

AppCache's opaque update behavior led to programmable Service Workers. A modern offline release has separate control plane (messages, release pointers, progress), data plane (cached shell/font bytes), browser lifecycle, and irreplaceable owner records. Committed study [437](https://github.com/yhappcom/web-manager/blob/main/research/437_stage8_pwa_control_catalogue_atomic_cutover_integrated_20261020.md) showed the cross-worker Cache API catalogue migration race; [431](https://github.com/yhappcom/web-manager/blob/main/research/431_stage8_pwa_http_cache_vs_cache_api_update_contract_20261020.md) distinguished HTTP cache, Cache API, Worker update and owner-data durability. A 2026-10-21 local source audit additionally quantified redundant warm-launch full-byte hashing.

**Principle:** a diagnostic READY/progress state is not release authority or future byte integrity. Authorization must be lifecycle-bound, verify fresh candidate bytes, fence mixed writers, atomically commit metadata, and independently hash the exact bytes served. Work optimization must not weaken integrity, data preservation or cross-generation correctness.

## SYNTHESIS — source-derived authority and workload

1. The mandatory font/notice set is **724 WOFF2 + 148 notice resources = 872**, plus shell count `S` (actual NORMAL shell count not obtained). `valid` performs `Cache.match` → full `arrayBuffer` → SHA-256; `inspect` runs sequentially.
2. Under the explicit assumptions *warm ready; candidate=served; all cached; promotion and precache messages both complete*, promotion scans candidate three times (direct + status candidate + status served), and precache checks 872 reusable font/notice entries plus candidate inspect. The static budget is **`4S + 4360` full-body digest calls**; synthetic `S=6` gives 4,384. This is **not** measured CPU, energy, actual bytes or browser latency.
3. The message handler checks `api` and `type` but not `event.source` authorization. Repeated messages can request repeated full scans. This is a **same-origin work-amplification hypothesis**, not evidence of a remote unauthenticated attack: relevant same-origin execution is a precondition. Client checks help constrain commands but cannot prevent same-origin CacheStorage mutation.
4. Status READY is point-in-time. Same-origin script, another Worker or browser storage eviction can invalidate it; serve-time exact-byte SHA must remain. Coalescing overlapping **advisory** status scans is plausible, but reusing status as permanent admission authority is not.
5. A waiting Worker receiving `START_PRECACHE` can write the predecessor's legacy Cache JSON before activation; therefore the future IDB migration in 437 requires a **one-way writer-fenced cutover** and no authoritative waiting/install mutations. A Promise queue inside one Worker is not cross-worker locking.
6. The UI can start before offline preparation completes. Visible Flutter UI ≠ offline readiness; local record saved ≠ Sync ACK; cached shell ≠ independent `.lbk` backup.

## MINTTAP DECISION — bounded Engineering candidate, not product patch

- Split cheap **PROGRESS** (explicitly advisory) from fresh **VERIFY** (complete integrity), **STAGE** (immutable candidate), lifecycle-authorized **ACTIVATE**, byte-verified **REPAIR**, and per-response verified **SERVE**.
- Coalesce only overlapping advisory scans within a Worker global; sequential status calls are not permanently cached. A local generation counter cannot detect every external Cache API mutation, so promotion and serve never trust advisory status.
- Remove page-message promotion authority in the proposed successor protocol. Installing/waiting Worker stages immutable bytes without writing legacy authoritative control. Once old clients drain, activation verifies the latest legacy snapshot and atomically commits successor metadata in dedicated IndexedDB, with no asynchronous cache/hash work inside a readwrite transaction. Use `tx.oncomplete` as commit evidence; never equate it with CacheStorage atomicity.
- Retain predecessor bytes safely, fail closed on missing/corrupt assets, and never clear owner Sembast/IndexedDB records, unsynced edits/outbox, import history or independent backups to repair release metadata. Do not `skipWaiting` or roll back to an old Cache-only Worker as an unvalidated shortcut.
- Benchmark actual hashed bytes, cache I/O, CPU, event completion, navigation/critical-task latency and power on exact NORMAL artifacts before optimizing font groups. Any font/notice reduction needs Design Studio accessibility/glyph and license review.
