## SOURCE / history / architecture

Service Worker installation waits for `install` event `waitUntil()` promises and fails if one rejects; that does **not** roll back Cache Storage writes performed before rejection. Source: https://www.w3.org/TR/service-workers/ . WebKit's quota and origin eviction policy is not a guarantee of available free space or user-record durability: https://webkit.org/blog/14403/updates-to-storage-policy/ ; WHATWG storage https://storage.spec.whatwg.org/ .

LogMate source: https://github.com/yhappcom/logmate/blob/6101666530cb706a042ac82614c840af441895b1/tool/pwa_precache.dart . The Worker `install` handler first caches all shell entries (six concurrent workers, three retries), writes candidate metadata, then downloads/verifies all fonts and font notices. Cache Storage writes occur per item, with no rollback on a rejected install. No automatic cache retirement is implemented; previous verified versions are deliberately preserved. This is a sensible non-destructive starting point, not a complete storage-pressure policy.

## SYNTHESIS / cross-track decisions

**Installation failure ≠ transactional Cache Storage rollback.** Failed candidate bytes can consume the same origin's finite storage budget as user data. One missing notice, font or debug symbol currently blocks the entire candidate because all 952 manifest entries are mandatory. This is a source-level dependency, not proof any particular resource is removable.

Using archived sizes only, hypothetical simultaneous cache payloads are 64.91 MiB for one version, 106.98 MiB for two shell generations sharing a font set, or 129.82 MiB for two complete versions with different font sets. These are arithmetic stress envelopes, not observed quota or actual disk usage; browser deduplication and other origin state are unknown. WebKit origin-level eviction means preserving old shell caches is not equivalent to backing up Sembast records or the outbox.

**MINTTAP DECISION (conditional Engineering handoff):** classify `critical_offline`, `deferred_offline` and `not_deployed` before generating manifests/Worker hashes. Exclude incidental hidden build markers only after confirming they have no runtime consumer. Do **not** automatically drop fonts, renderer variants, symbol maps or license notices: Engineering must validate offline renderer/fallback behavior, and applicable license/notice delivery requirements remain OPEN. Avoid broad `include-hidden-files: true` and origin-wide clear/reset. Verify separately built normal PWA after upload and Firebase served bytes, then first install/upgrade/offline on real browsers, then independent `.lbk` restore and physical/managed iPad.
