## 146 checkpoint
- Change handling separates delivery, source authentication, semantic admission and independently observable current state; none is treated as equivalent to the next.
- Material change events enter as candidates and cannot fan out through the assurance graph until source/identity/type/generation semantics are admitted.
- Stable event identity and idempotent processing prevent duplicate delivery from creating duplicate dependency transitions; timestamps alone do not define authoritative ordering.
- Event-driven monitoring is not completeness proof. Periodic/event-triggered current-state reconciliation detects missed events, rollback suspicion, divergence and unobservable state.
- Reconciliation preserves mismatch provenance before normalization and cannot silently rewrite history to match the latest observation.
- Reconciliation authority is bounded: ability to observe provider/runtime state does not grant arbitrary trust-floor/reset authority.
- Independence is consequence-based and requires failure-domain analysis; two APIs backed by one compromised control plane are not two independent observers.
- Event-channel outage degrades monitoring coverage. Recovering final current state does not prove complete intermediate transition history.
- For PWA/EFB, server rollout events, Service Worker/device activation and managed-iPad state remain separate evidence scopes; local irreplaceable data remains preserved while remote authority can stay gated.
