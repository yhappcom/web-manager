## 116 material findings
- preservation and containment are coordinated but distinct gates; credible continuing harm must not be prolonged merely to preserve cleaner evidence;
- client isolation and remote authority containment are different planes. An offline suspect EFB can coexist with still-valid stolen sessions, accounts, deployment credentials, domain/provider authority or unsafe fleet exposure;
- prefer containment that revokes/freezes unsafe remote authority while preserving irreplaceable local domain data where architecture permits;
- evidence sacrifice can be justified when necessary to stop active harm, but expected loss, alternatives, authorization, timing and residual uncertainty must be recorded explicitly;
- indiscriminate wipe/site-data clearing is not a generic containment default for an offline-authoritative EFB because it may destroy the only legitimate records;
- reconnect after containment is itself a controlled transition: trust/update recovery and operation replay must remain separate gates;
- incident telemetry remains purpose-limited; an incident does not create unlimited collection authority.

## Persistent guards added by 116
`evidence preservation valuable ≠ active compromise may continue for evidence convenience`.  
`containment action destructive to evidence ≠ containment action unjustified`.  
`suspect client offline ≠ compromised account/session revoked`.  
`one device isolated ≠ fleet contained`.  
`origin restored ≠ stolen deployment credential revoked`.  
`network isolation ≠ remote authority containment`.  
`evidence is perishable ≠ every containment action should wait`.  
`containment urgent ≠ wipe is automatically the safest containment`.  
`local record irreplaceable ≠ compromised executable authority must remain active`.  
`remote containment complete ≠ reconnect safe`.  
`reconnect required for update ≠ replay should be enabled simultaneously`.  
`incident response need ≠ unlimited telemetry collection authority`.
