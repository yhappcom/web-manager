## 130 checkpoint
- Recovery is capability-specific: restore the safest useful subset that can be justified now; availability pressure must not silently restore stale authority.
- NIST resilience permits degraded operation while maintaining essential operational capability; degraded mode is not a synonym for weakened security.
- Decompose PWA recovery into local launch/read/capture/export, authentication, policy/client generation, queue/transmit/reconcile, remote read/write/destructive mutation and update/migration capabilities before choosing fail-closed vs degraded behavior.
- Use fail-closed for uncertain consequential authority/destructive mutation; safe degradation for bounded local utility; fail-visible when a capability is unavailable or uncertain.

## Persistent guards added by 130
`degraded operation ≠ weakened authority by default`.  
`screen available ≠ capability safely recovered`.  
`application available ≠ every capability available`.  
`RTO pressure ≠ authorization bypass justification`.  
`availability restored ≠ integrity restored ≠ authority restored`.  
`fail closed ≠ make all local data inaccessible`.  
`graceful degradation ≠ silent stale behavior`.  
`queued ≠ sent ≠ acknowledged ≠ reconciled`.  
`network returns ≠ queue replay automatically safe`.  
`new worker available ≠ safe immediate activation for every client`.  
`client unsupported for remote write ≠ client data should be destroyed`.  
`network healthy ≠ degraded mode exit criteria satisfied`.  
`UNKNOWN ≠ NORMAL`.
