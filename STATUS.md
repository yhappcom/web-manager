## 047 — Web Color, Surfaces, State & Brand Application Literacy

`research/047-stage4-web-color-surfaces-state-brand-application-literacy.md`  
**FOUNDATION/PRACTITIONER CHECKPOINT: PASS.**

Core model:

`content/task role → semantic color role → foreground/surface pair → interaction/state cue → user/UA color environment → rendered result → accessibility + browser + human validation`

Reusable output: **Web Color / Surface / State Contract**.

Retained judgment:
- semantic color obligations precede exact palette values;
- brand identity, action and semantic state are distinct roles even if a validated system later shares values;
- color cannot be the sole carrier of required information/action/state meaning;
- text contrast, non-text contrast, hierarchy quality and human readability are distinct review layers;
- `color-scheme` communicates supported schemes but does not generate an author palette;
- forced colors can replace author colors and remove shadows/background treatments, exposing color-only state failures;
- `forced-color-adjust: none` is exceptional and must not be used merely to preserve branding;
- modern/wide-gamut CSS color is capability, not a MintTap requirement without demonstrated value and fallback/validation;
- app screenshots remain product evidence and should not be recolored into false consistency.
