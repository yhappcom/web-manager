## 114 material findings
- IndexedDB transaction completion/durability is persistence evidence, not user-authorship, semantic-integrity or provenance evidence;
- evidence must be separated by authority domain: current local value, local history, user-intent evidence, device/app generation, remote acknowledgement, independent audit evidence, backup snapshots and domain reconciliation are not interchangeable;
- a record and its audit entry stored under the same compromise-capable same-origin authority are not two independent witnesses;
- remote acknowledgement is useful only when it identifies the operation/state semantics actually accepted. Bare HTTP success or `synced=true` is inadequate incident provenance;
- authenticated/cryptographically intact operations can still be attacker-generated if hostile code held legitimate session/device authority. Operation integrity, user intent, domain validity and current authorization are distinct;
- append-only/event-sourced models improve reconstruction only when the tamper boundary is independently protected; an application convention is not a security boundary;
- client wall-clock timestamps do not establish trusted chronology. User-entered domain dates, local order, server receipt/version and trust/schema generations should remain distinct where available;
- `unverifiable` is a legitimate recovery classification. If independent historical integrity evidence never existed, recovery must preserve uncertainty rather than manufacture retrospective certainty;
- forensic/audit usefulness does not justify duplicating full sensitive records, tokens or secrets into telemetry;
- for offline-authoritative EFB-like data, preserve uncertain records while blocking uncertain authority/replay until reconciliation.
