## 039 — User Action, System State, Feedback, Error & Recovery Foundations

`research/039-stage3-user-action-system-state-feedback-error-recovery-foundations.md`

**FOUNDATION/PRACTITIONER CHECKPOINT: PASS.**

Core model:

`goal → action possibility/signifier → constraint → articulation → requested transition → accepted? → pending/working? → committed state → feedback → recovery/reversal → continuity`

Retained judgment:
- usability, interaction design and visual presentation are separate questions;
- affordance/action possibility and signifier/discoverability are not synonyms;
- action possibility, mapping/scope, availability and commitment truth are separate gates;
- significant interactions need explicit state models before styling;
- forms are stateful tasks, not field collections;
- prevention/constraint/validation/error identification/correction/confirmation/undo/recovery solve different problems;
- destructive protection depends on consequence × reversibility, not universal confirmation;
- async operations may require pending/confirmed/known-failed/canceled/outcome-unknown distinctions;
- timeout does not prove failure and retry safety depends on API/business-effect semantics;
- optimistic UI needs reconciliation/rollback policy;
- disabled, unavailable and pending are not synonyms;
- continuity can involve draft, filters, focus, pending operation and authoritative data separately;
- browser-native controls/forms are the baseline before custom replacement;
- standards/expert review does not prove real user usability.

Reusable output: **Interaction Contract**.

## 040 — User Goals, Task/Journey Modeling, Cognition, Expectation & Friction Foundations

`research/040-stage3-user-goals-task-journey-cognition-expectation-friction-foundations.md`

**FOUNDATION/PRACTITIONER CHECKPOINT: PASS.**

### Core task/journey model

`entry/context → user goal → prerequisites → task/state sequence → decision/commitment → completion / unresolved / abandoned → recovery/escalation`

### Retained judgment

- goal, task, step, action, control and system operation are different layers;
- journeys should model meaningful user work/state/commitment, not merely marketing/analytics funnels;
- the user critical path is the **smallest justified work sequence**, not the fewest clicks/pages;
- a step is justified by task necessity, protection, informed decision, auth/authorization, required evidence, policy/legal obligation, disambiguation or recovery — not by legacy internal structure alone;
- fewer steps are not automatically easier; combining steps can increase decision/search/error cost;
- working-memory evidence does **not** justify universal UI item-count rules such as 4±1 or 7±2;
- reduce unnecessary recall by externalizing/preserving current and prior-step context;
- recognition-vs-recall applies across whole journeys, not only controls;
- interruption recovery requires enough evidence to reconstruct location, prior commitment and remaining work;
- Hick/Hyman choice-reaction evidence concerns uncertainty under bounded tasks; it is **not** a rule that fewer menu items are always better;
- progressive disclosure is information timing by decision dependency, not aesthetic cleanup;
- eligibility, material cost/consequence, privacy/data-use facts, unsupported states and comparison-critical facts should not be hidden until after substantial effort or commitment;
- consistency means stable learned semantic contracts, not pixel sameness;
- friction is classified as **necessary / protective / accidental / manipulative-obstructive**;
- protective friction can be good when proportional to consequence/reversibility;
- accidental friction should be removed; manipulative asymmetry is an ethical risk and can become a legal/policy risk depending on service/jurisdiction;
- conversion improvement alone cannot prove UX quality or informed/free choice;
- reduce relevant uncertainty before consequential commitments instead of optimizing raw step count;
- real MintTap cognition/task-performance claims require actual flow evidence and human validation.

### Explicitly rejected folklore

Do not use as professional rules:
- “four items because working memory”;
- “7±2 menu items”;
- “Hick's Law means always show fewer choices”;
- “one question per page automatically lowers cognitive load”;
- “fewer screens/clicks always means better UX”;
- “all friction is bad”;
- “higher conversion proves a better journey.”

### Primary/current evidence checked 2026-09-15

- ISO 9241-210:2019, confirmed current by ISO in 2025;
- GOV.UK Service Standard/Service Manual on user needs, whole-problem journeys and usability benchmarking;
- W3C Cognitive Accessibility guidance on memory dependence and interruptions;
- Cowan 2001 working-memory capacity review;
- Hick 1952 and Hyman 1953 choice-reaction research plus modern limitations review;
- FTC 2022 dark-pattern report/enforcement examples;
- Regulation (EU) 2022/2065 Article 25, with explicit scope caveat;
- Design Studio Interaction 007, I001 and Web W001;
- current Design Studio Web and Layout/Interaction status.

### Reusable output — Task/Journey Contract

For consequential/multi-step journeys specify:
1. user outcome and actual completion condition;
2. entry contexts and context already known;
3. prerequisites and when they must be disclosed;
4. task sequence and reason for every step;
5. information already known vs genuinely required input;
6. cognitive dependency — recognition, recall, assumed knowledge, prior-step summary;
7. decision structure and simultaneous-comparison needs;
8. interruption/resumption state;
9. friction classification and justification;
10. trust/uncertainty questions before commitment;
11. state/commitment/recovery linkage to 039;
12. standards, analytics, support and human-validation evidence required.

### 040 failure taxonomy

- goal mismatch;
- scope fragmentation;
- redundant work;
- premature work;
- recall dependency;
- choice-structure failure;
- expectation-transfer failure;
- interruption/resumption failure;
- commitment uncertainty;
- accidental friction;
- protective-friction mismatch;
- manipulative asymmetry;
- evidence failure.
