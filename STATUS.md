- **Proof validity is claim-, dependency-, generation- and evidence-specific.** Stored PASS is not automatically current.
- **Material change invalidates affected proof closure immediately.** Graph-directed incremental revalidation is preferred only where the unaffected cut is itself evidenced; UNKNOWN impact widens revalidation.
- **Time is a freshness backstop, not the primary truth model.** Change can invalidate before TTL; age can force refresh even without observed change.

- **No global distributed transaction is assumed.** Claim-specific per-domain generation/fence vectors and monotonic current-selection semantics contain races without pretending browser/provider/offline state is physically simultaneous.
- **Proof issuance and consumption are separate TOCTOU boundaries.** Enforcement re-checks the proof against the current security/admission floor and known invalidations at use time.
- **Revalidation races use bounded restart semantics.** A change during assessment invalidates affected observations; unaffected evidence is reusable only when its dependency cut remains proven.
- **PWA proof is client-relative where effective Service Worker control matters.** Published/installed/waiting/active/controller and data/schema/policy generations remain distinct.
- **Long-offline return during revalidation preserves unique local data first** while consequence-bearing queued work waits for current admission and is not grandfathered by creation-time proof.
- **Rollback/PITR can fork proof lineage.** Restored “latest” local rows do not regain current authority until lineage/current-selection convergence is established.
- Historical proof remains available for audit but cannot satisfy current admission merely because it has the newest timestamp in one restored store.
