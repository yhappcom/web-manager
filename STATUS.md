## 136 checkpoint
- Per-item authenticity is not sequence integrity. Inclusion, append-only consistency, freshness, non-equivocation, semantic legitimacy and current authorization are separate claims.
- Omission, reorder, rollback, prefix/suffix truncation, branch splice, equivocation, checkpoint substitution and re-export lineage laundering are distinct failure classes.
- A checkpoint commits to scoped history; an anchor is a retained checkpoint/attestation in a sufficiently different failure context. Same mutable storage for history and its only checkpoint is not independent rollback evidence.
- One internally valid branch cannot prove no unseen fork exists. Non-equivocation assurance needs comparison against prior/independent state appropriate to the threat model.
- Legitimate offline device divergence is not automatically malicious equivocation; preserve branches until explicit reconciliation/admission.
- Compaction/export/import continuations must bind source lineage/range/predecessor and transformation provenance so valid segments cannot be silently spliced into a false history.
- Blockchain/public transparency infrastructure is not a generic requirement. Checkpoint/anchor strength must be proportional to consequence, adversary model and recovery objective.
