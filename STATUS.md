## 048 — Web Imagery, Iconography, App Screenshots & Product Demonstration Literacy

`research/048-stage4-web-imagery-iconography-app-screenshots-product-demonstration-literacy.md`  
**FOUNDATION/PRACTITIONER CHECKPOINT: PASS.**

Core model:

`communication purpose → evidence/semantic role → source/provenance → representation/crop → responsive context → accessible equivalent → product/store consistency → lifecycle/freshness → browser/human validation`

Reusable output: **Product Media / Non-Text Contract**.

Retained judgment:
- responsive resource selection and art direction are distinct; a responsive crop must preserve claim-relevant evidence;
- image alternatives follow purpose/context, not a mechanical description rule;
- ordinary website copy should remain real text rather than image text;
- app screenshots/demos are product evidence and require provenance, presentation integrity and lifecycle ownership;
- website↔store continuity requires truthful product representation, not identical composition;
- icon glyph, semantic meaning, control role, accessible name and state are separate layers;
- icon-only controls need a defensible task/space reason and later recognition/usability validation;
- screenshot recoloring/compositing must not imply an app UI that is not shipped.
