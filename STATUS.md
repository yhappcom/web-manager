# Continuous expert maintenance checkpoints
083 — **PWA Storage Durability & Service-Worker Standards Change Watch — PASS (2026-09-16).**

Material findings:
- W3C Service Workers continues active Candidate Recommendation Draft publication through 2026-08-12; preserve durable lifecycle semantics but keep implementation edge cases on CHANGE WATCH;
- `StorageManager.persist()` is a persistence request whose grant is browser-controlled; `persisted()` is state evidence; `estimate()` is diagnostic quota/usage evidence;
- `storage API available ≠ persistence granted ≠ independent backup ≠ tested restore`;
- current WebKit storage policy supersedes historical fixed-quota folklore: modern Safari/WebKit uses disk-relative origin/overall quotas and standalone Home Screen Web Apps receive the same origin/overall quota treatment as browser use;
- the 2018 WebKit 50 MiB Cache API figure is historical evidence and must not be generalized as current Safari quota policy;
- eviction remains possible under defined conditions; irreplaceable local records therefore require an independent recovery path rather than reliance on browser storage alone;
- for LogMate/EFB-like use, exact managed-iPad artifact/device tests remain required for persistence grant, long-offline survival, schema migration, worker/cache update, storage pressure, restore and recovery claims.

New durability acceptance chain:
`data criticality → acceptable loss window → local persistence → offline survival → sync/reconciliation → independent copy → restore → tested recovery`.
