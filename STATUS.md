## 162 checkpoint
- Intentional deletion is a versioned provenance transition, not silent history rewriting; payload availability and lineage continuity are separate claims.
- Deletion is decomposed into logical availability, authoritative retention state, replica/cache/search/analytics propagation, backup recoverability, cryptographic recoverability, offline/export copies and minimum lineage residue.
- NIST SP 800-88 Rev.2 is the current final media-sanitization baseline; application deletion is not itself sanitization proof.
- Cryptographic erase is only defensible when key scope/hierarchy, wrapped/derived/unwrapped copies, backup/escrow keys, provider behavior and plaintext projections are validated.
- A retained hash/commitment is not automatically anonymous or privacy-neutral; low-entropy dictionary confirmation and stable cross-record linkability must be assessed.
- Proof-minimizing lineage retains only what a declared proof needs; a commitment is optional and must not become a shadow copy or correlation oracle.
- PITR/backup restore must reconcile against the current deletion/retention floor before restored content becomes ordinarily servable.
- Long-offline PWA/device state cannot silently republish server-intentionally-unavailable content, while unique local user/flight data must not be destroyed absent verified product/legal authority.
- UX must distinguish `INTENTIONALLY UNAVAILABLE`, `REDACTED`, `RETENTION HOLD`, `MISSING/SYNC UNKNOWN`, `CORRUPT/UNVERIFIABLE` and local-copy/remote-state-change conditions.
- EDPB Guidelines 01/2025 evidence used for pseudonymisation remains consultation-stage and is CHANGE WATCH, not a final legal/product conclusion.

## Persistent guards added by 162
`row deleted ≠ data destroyed`.  
`application delete succeeded ≠ backups sanitized`.  
`ciphertext retained + one key destroyed ≠ cryptographic erase proven`.  
`hash retained ≠ content anonymous`.  
`salted hash ≠ automatically non-identifying`.  
`cryptographically strong hash ≠ privacy-safe commitment`.  
`payload unavailable ≠ event never existed`.  
`tombstone retained ≠ payload retained`.  
`tombstone present ≠ deletion propagated everywhere`.  
`backup exists ≠ ordinary application may resurrect intentionally deleted data`.  
`offline copy exists ≠ server deletion failed outside the declared server-control scope`.  
`offline copy exists ≠ safe to silently republish deleted server data`.  
`INTENTIONALLY UNAVAILABLE ≠ CORRUPT ≠ NOT YET SYNCED`.
