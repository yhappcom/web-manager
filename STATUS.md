## 158 checkpoint
- Recovery effects are modeled as consequences with durable identity, ceremony generation, target authority domain, commit certainty, reversibility class, current-state dependency and causal provenance.
- Compensation is a new current-policy-authorized transaction, not authority inherited from the original/aborted ceremony.
- Effects are separated into uncommitted, reversible, compensatable, irreversible and unknown; an inverse API does not by itself prove semantic reversibility.
- Compensation authority is capability-scoped and should separate investigation/proposal/authorization/execution/verification semantics where consequence warrants it.
- Current target state and concurrency must be revalidated before compensation; stale snapshot restoration can destroy legitimate work.
- Idempotency supports retry but does not prove current authorization or semantic validity; ACK/result uncertainty must be reconciled before duplicate execution.
- Irreversible effects move to containment/correction/notification/residual-risk governance rather than rollback theater.
- Original effect and compensation remain causally linked in provenance; compensation never erases the historical effect.
- Long-offline PWA/iPad local data remains preservable independently of remote recovery-effect authority; stale SW/offline queues cannot broaden compensation authority.
